# SIFT 0.9 worklog

## Entry — offset-target numerics in `target_cv` `smooth="auto"` (PR #72, on top of `6017df6`)

- Objective: Fix the P1 numerical defect in the `target_cv_smoothing="auto"` empirical-Bayes shrinkage, and bring the status documents up to the current CI head.
- Latest steering: Compute every moment on `y - prior` with a stable two-pass weighted variance, in the single engine, so the out-of-fold, full-fit, weighted, grouped, and time-aware paths all inherit the fix; preserve ordinary-scale results and sklearn `"auto"` parity.
- Constraints: Unchanged — sklearn `>=1.3,<2`, existing unsafe encoders behind `allow_full_data_target_encoding=True`, fixed-k rejection of `groups`/`time`, the 58-name top-level surface, default `cat_encoding="none"`. One-hot remains blocked on F3 block-aware selection.
- Decisions: The `"auto"` shrinkage is translation *invariant* and scale *equivariant*; both are now stated contracts with tests. `lambda_i` is scale-free, so scaling `y` by `s` scales the emitted effects by exactly `s`. The explicit-float smoothing path is centered too — algebraically identical, and it removes the same cancellation for free. Binary `target_cv` is deliberately unchanged and pinned, because a 0/1 target has no offset to cancel.
- Completed: `TargetCVEncoder` accumulates its centered sums, global target variance, and within-category sums of squared deviations on `y - prior`; `_weighted_group_ssd` replaces `E[y^2] - E[y]^2` with a genuine two-pass weighted formula; `_auto_smoothed_encoding` shrinks in centered space so the final `estimate - prior` cancellation disappears; `_centered_targets` refines the weighted prior once so its own rounding error does not leak into the effects. Sixteen tests added. Status documents updated: `docs/specs/0.9-next-steps.md` (CI head `6017df6`, release-workflow language, three adversarial-review rounds), `docs/specs/0.9-product-layer.md` (rev 15, E correction landed, numerics note in §E.1), `docs/release-notes.md`, and this worklog.
- Current state: Stages 1 and 2 are complete. PR #72 (`stage1/0.9-corrections`) was green at `6017df6` on `test (3.10)`, `test (3.11)`, `test (3.12)`, `test-catboost`, `min-pins`, and `wheel-smoke`. This commit sits on top of that head and has not yet had its own CI run. The asset-only GitHub-release workflow is on the default branch since PR #71 (`d10afef`), so no release event can publish to PyPI. Stage 3 (deprecation ledger, then documentation and release preparation) is the open work.
- Next action: Stage 3 — resolve the deprecation ledger (§3.1), then documentation and release preparation (§3.2). Keep `__version__="0.9.0a1"`.
- Blockers: Unchanged. No PyPI publication; a `v0.9.0` tag/GitHub Release stays an explicit owner action after the release PR merges.
- Decisive verification: Reproduced before the fix on a 300-row / 6-level regression fixture. `fit_transform(X, y)` vs `fit_transform(X, y + 1e8)`, max difference in the centered OOF encoding: 0.185 plain, 0.076 integer-weighted, 0.112 float-weighted, 0.170 grouped, 0.306 time-aware; 0.051 in the target-blind `transform`. On two near-tie designs the error decided the selection: `select_mrmr(k=1)` flipped `['cat'] -> ['numeric']` (encoding difference 0.157) and `select_cefsplus(k=1)` flipped `['numeric'] -> ['cat']` (0.230). An explicit `smooth=5.0` differed by only 4.4e-8 at the same offset, which localized the defect to the empirical-Bayes path. After the fix: <=5.6e-16 against the target the shifted run actually sees in all five contexts, <=1.9e-9 against raw `y` (float64 resolves only ~1.5e-8 near 1e8, so `y + 1e8` cannot carry `y` more exactly), and both selector flips are gone. Twelve of the sixteen new tests fail against the pre-fix encoder; the four that pass by design are the three scale-equivariance guards and the binary pin. sklearn `smooth="auto"` parity holds at 8.9e-16 over twelve seeds. Full suite 1,713 passed / 25 skipped under warnings-as-errors (1,697/25 before, +16); ruff and `git diff --check` clean.

## Entry — adversarial review rounds on PR #72 (`stage1/0.9-corrections`, base `4de1957`)

- Objective: Close the six findings of an independent adversarial review (Grok) of PR #72, and record Stage 1/Stage 2 completion honestly.
- Latest steering: Fix every finding; do not change selection numerics for finding 2 — fix the over-claim instead.
- Completed: Round 1 (`020e082`) closed all six findings and marked Stages 1 and 2 complete in `docs/specs/0.9-next-steps.md` with the PR #72 CI evidence (test 3.10/3.11/3.12, test-catboost, min-pins, wheel-smoke all green) and the four CI-only fixes that were needed (full-history checkout for the gate-provenance test, the nested auto-k stub keyword, CatBoost seed warnings, platform-stable gate rendering). Round 2 (`6017df6`) closed three verification leftovers: the `docs/API.md` sentence still requiring an explicit smoothing float on weighted/grouped/time-aware `target_cv`, a near-unique boundary test that could not fail, and a workflow comment claiming the whole matrix installs the NumPy 2.5.2 band.
- Decisions: `target_cv_smoothing="auto"` is valid on the weighted, grouped, and time-aware paths — the empirical-Bayes prior is the unweighted formula with counts replaced by weighted row mass, so it was always well defined there and the gate was simply wrong. The only genuinely undefined case, a fitting slice with no positive weight mass, still raises for both `"auto"` and an explicit float, and is pinned. Near-unique identifiers keep their numerics: a level appearing twice in training legitimately carries its sibling row's target, so this is documented as the boundary of the centering guarantee (drop ID-like columns, or pass `groups=`) rather than engineered away.
- Decisive verification: All six round-1 findings reproduced on `4de1957` before the fix and confirmed after — weighted/grouped/time `"auto"` raised `ValueError` on all six probed entry points and now succeeds; the 300-ID x 2-row fixture gives `corr(enc, y) = 0.879` with `select_mrmr(k=2) -> ['id', 'weak']` (unchanged by design, now pinned), while `groups=` drives the same column to exactly zero; `fit()` reported `n_splits=5` against `fit_transform`'s 4 and now reports 4. Weighted `"auto"` matches integer row replication exactly (0.0) and the full-fit map matches sklearn's `"auto"` to 2.8e-17. Full suite green under warnings-as-errors; ruff, `git diff --check`, and a YAML parse of the workflow clean.
