## 1. Why 0.9 exists

The 0.8.0 line was a correctness campaign: four hardening rounds closed the silent-failure paths,
the statistically-backwards defaults, the cache contracts, and the packaging blockers. What it
deliberately did not touch is the *product layer*. Today:

- **55 top-level exports**, including auto-k helpers the docs themselves call experimental or
  failed-gate. A new user cannot tell the load-bearing 12 names from the research surface.
- **5 incompatible result types** (`FilterSelectionResult`, `KnockoffSelectionResult`,
  `BorutaResult`, `CatBoostSelectionResult`, `FeaturePathEvaluationResult`) plus two entry points
  (`StabilitySelector`, `permutation_importance`) with no result object at all.
  `selected_features` is an attribute on three of them and a *method* on `BorutaResult`;
  `StabilitySelector.selected_features_` holds indices where the other classes hold names.
- **49 `AutoKConfig` fields × 14 `k_method`s**, with overlapping-but-distinct pairs a user must
  disambiguate (`n_splits` = evaluate folds vs `xfit_folds` = fold-curve folds; `elbow_patience`
  vs `stop_patience` govern different stops; `objective_n_eff` overlaps `n_eff_mode=<float>` for
  objective/posterior and gain-test effective-sample-size resolution) and one accepted configuration value that is currently
  reserved and unimplemented (`xfit_mode="exact"`; both public and low-level xfit paths reject it).
- **Convention drift**: `groups=` arrays vs `group_col=` names vs columns-inside-`X` (CatBoost);
  `random_state` 0 / 42 / None; `n_jobs` 1 / −1; `verbose=True` with **43 `print(` sites** and one
  `logging` user; `alpha` means an L1 penalty in one module and a significance level in two others;
  `select_cached` has four positional return shapes.
- Before workstream D, sklearn integration stopped at `get_feature_names_out`: there were no
  `SelectorMixin` support-mask semantics, no `inverse_transform`, and no metadata-routing
  requests. D closes that product-layer gap while preserving every selector family's output order.
- Before E1, the categorical story was "raise with a good message." E1/E2 now provide an
  in-library unweighted, weighted, grouped, and time-aware path for regression/binary targets +
  string columns. The unique-level fold-prior correction has landed: every emission is centered on
  the training prior that produced it, one SIFT engine serves all three fold kinds, and
  `smooth="auto"` is defined by weighted row mass. §E.2 records the one boundary that correction
  does *not* cover — a near-unique level that recurs in-fold still transmits its sibling rows'
  targets, which is ordinary target-encoding behavior rather than a fold marker.

0.9 is the release where the algorithms stay put and the *interface* catches up, organized around
one mental model:

> Every selector is "rank candidates → build an ordered path → apply a stopping rule → return a
> subset". Knockoffs, Boruta, and stability are "score every feature → threshold". The API should
> say so.

**Non-goals for 0.9**: new estimators of MI, changes to the copula/log-det/knockoff math, formal
Meinshausen–Bühlmann error control for stability, GPU work, polars-native internals.

### 1.1 Compatibility policy (the campaign's hard constraint)

**0.9 is strictly additive.** Concretely:

- Every 0.8 call — same arguments, same defaults — produces the same selections, the same return
  types, the same output ordering, and every existing export. `__all__` grows (55 existing names
  plus the three 0.9.0 additions — **58** total in 0.9.0); later 0.9.x additions are explicitly
  counted or module-scoped. Nothing is removed, no defaults change, no output order changes, no
  CatBoost `k` semantics change in 0.9.
- New behavior arrives only as **new options** (`output_order=`, `return_result=`, presets, option
  groups) or **new warnings**. Anything slated to flip does so in **1.0**, after a full 0.9 cycle
  of `FutureWarning`s emitted through
  `sift._deprecate.warn_deprecated(name, since="0.9", removal="1.0")`. The helper and its test
  utility are landed, and the two caller-facing warnings the policy actually requires in 0.9 are
  wired and covered by production tests: the `random_state=None` default-use `FutureWarning`
  (`StabilitySelector.fit`, `permutation_importance`, `catboost_select` and their wrappers) and
  the `sift.experimental` namespace `FutureWarning`. No other 1.0 flip claims a 0.9 warning —
  per the owner decision of 2026-09-02 the CatBoost `group_col`/`sample_weight_col` and stability
  `alpha` removals are struck from §4, so those aliases are permanent and deliberately silent.
- The 1.0 flips are enumerated **now**, in §4 (the deprecation ledger), so "what changes in 1.0"
  is a table, not a surprise. This resolves rev 1's contradiction between "every 0.8 call works"
  and its own default changes: those changes are all 1.0 items.
- Enforcement is mechanical, not aspirational: workstream B0 builds a **compatibility contract
  matrix** (parametrized tests over method × route × input type × options; §2.B0) plus golden
  selection snapshots, and every later PR in the campaign must keep it green.

## 2. Workstreams

Sizes: S ≈ a day, M ≈ 2–4 days, L ≈ a week+ of focused time including tests and docs. Rev 1

### 2.0 Stage 0 — close the outstanding defects before any snapshot is recorded (S) — **done**

Two defects existed on `main` at `be99df0` and are fixed alongside this rev (with regression
tests in `tests/test_release_readiness.py`); contract
snapshots must be recorded only on top of these:

1. `StabilitySelector`'s DataFrame `transform` contract was incomplete: missing or renamed
   selected columns raised a raw pandas `KeyError`, and a selector fitted on a positional ndarray
   raised `KeyError: "None of [Index(['x0'...])..."` when handed a DataFrame. Now: name-based
   selection still tolerates extra/reordered columns (pinned by test), missing/renamed columns
   raise a clear `ValueError`, and positional-fit + DataFrame input to `transform` or
   `tune_threshold` raises a clear `ValueError` directing the caller to pass an ndarray or refit
   on the DataFrame. Both methods share duplicate, missing-column, and generated-name guards.
2. The `auto_dense_*` router-field stripping missed two paths that rebuild configs: the Gaussian
   late **fallback** (built from the *original* config) and the **binary** auto router. Both now
   route through `_strip_router_only_fields`.

Subsequent review rounds surfaced five follow-ups, also closed and tested:

3. Stripping alone made binary log-loss `auto_dense_check` **silently ignored** (no log-loss
   dense-regime diagnostic exists). Binary log-loss CEFS+ automatic routing now **rejects**
   non-default `auto_dense_*` options with a `ValueError` naming them, instead of ignoring or
   mis-warning; default configs route cleanly with no unused-field noise. Binary Brier selection
   delegates to Gaussian CEFS+ and keeps the Gaussian dense-check behavior.
4. Duplicate DataFrame column labels corrupted `StabilitySelector` output width (selecting `a`
   from columns `a, a, b` returned both copies). Duplicate columns are now rejected at fit and at
   transform, and duplicate explicit `feature_names` are rejected.
5. `feature_names=[]` was treated as "absent" by preprocessing (`or`-falsy) but as "explicit" by
   the positional-input flag. `is None` is now the single absence test; an explicit empty list is
   rejected up front by the non-empty validation.
6. The Gaussian-fallback regression test exercised only the helper; it now drives the real
   `select_gaussian_auto_path` fallback dispatch (monkeypatched runner) and asserts the second
   dispatched config carries default `auto_dense_*` fields.

7. The smart-sampler path validated an explicit `feature_names` sequence and then silently widened
   it back to every numeric DataFrame column. It now preserves the requested subset and order,
   rejects scalar or unordered containers and nonnumeric explicit names clearly, and carries the
   resolved names into fitted metadata. Datetime and timedelta feature columns are rejected by
   the numeric feature-preprocessing guard; a configured datetime `time` metadata column remains
   valid metadata and is excluded from the feature set. Fold-local threshold tuning retains that
   metadata without widening the fitted subset. Exact tuple/MultiIndex and missing-value label
   identity is preserved, and unhashable labels fail validation. Stage-0 regression tests pin
   those contracts, including the exclusion of explicitly named group/time metadata columns.

### A. `SelectionResult` as a **protocol + adapters**, not a replacement (L)

Rev 1's inheritance plan is withdrawn: forcing five frozen dataclasses with different fields into
one hierarchy would break constructors, pickles, and `isinstance` checks, and the
`selected_features` attribute cannot coexist with Boruta's `selected_features()` method on one
class. Instead:

- **`SelectionView`** (a small concrete class) with the unified surface, and a
  `sift.as_result(obj, input_features=None)` adapter — plus a `.result_view()` method on each
  existing result class and a `result_view_` property on `StabilitySelector` — that wraps, never
  replaces. The view has two explicit identities whenever preprocessing expands or encodes
  columns: `raw_input` (`n_raw_features`, raw names, raw `columns_hash`) and `encoded_output`
  (`n_encoded_features`, encoded names, encoded `columns_hash`, and a raw-to-encoded mapping).
  A complete `raw_table` is one row per caller-supplied column; partial legacy adapters expose only
  rows they can prove and set `metadata["table_complete"] = False`. `encoded_table` is one row per
  fitted encoded column when that representation is available. `support_`/`indices` refer only to the raw input
  width, while `encoded_support_`/`encoded_indices` refer only to the encoded output width; no
  single mask is promised to represent both widths. Not every legacy object can reconstruct either
  full identity (e.g. `CatBoostSelectionResult` does not carry the pre-prefilter column list), so
  incomplete adapters set the corresponding fields to `None` and
  `metadata["table_complete"] = False`. Workstream A ships a per-adapter completeness matrix as
  documentation and tests:

**Workstream A implementation status (complete).** The core `SelectionView`, JSON-safe schema version `"1"`,
top-level `as_result`, and adapters plus `.result_view()` methods for `FilterSelectionResult`,
`KnockoffSelectionResult`, `BorutaResult`, `FeaturePathEvaluationResult`, and
`CatBoostSelectionResult` are implemented. Fitted `StabilitySelector` is also implemented through
a non-cached `result_view_` property; its table is complete over the fitted candidate namespace and
its frozen subset transform retains neither training rows nor coefficient matrices, and it follows
the fitted selector's `output_order` for `features`, `indices`, `path_rank`, and that frozen
transform. Result-only transforms remain unavailable by design. Feature-path evaluation, CatBoost,
and every automatic-k filter route have normalized score curves. Auto-k producers build the
`k`/`criterion`/`criterion_se`/`selected` payload from their own route diagnostics and store it in
`diagnostics_["auto_k_curve"]`, so adapters consume a normalized payload rather than guessing
method-specific columns; `knockoff_path` and `consensus` report an explicit
`curve_unavailable_reason` because their diagnostics are not k-indexed. Fixed-k filter, knockoff,
and Boruta results retain no route-level curve. Auto-k filter producers also retain the same
complete ranking their fixed-k twins produce, so auto-k views are table-complete.
`select_fdr` records `n_features_input` separately from the post-screening `n_features`, which lets
the knockoff adapter build `support_` and emit `reason_dropped` rows without `input_features`.
`permutation_importance(..., return_result=True)` now returns a module-scoped
`ImportanceResult` with a raw-position-by-repeat score-drop matrix and a complete
`ranking_only` view, while the historical DataFrame remains the default. The seven-family core
adapter acceptance criterion is complete. Cached and Gaussian filter result paths add explicit
`store_proxies=True` support: they retain only a bounded float32 correlation block, expose
duplicate-safe positional lookup, and preserve default result objects and returns. Partial views
reject misleading table-only plots, and JSON serialization reports proxy metadata without
embedding the correlation block. Broader cluster aggregation remains Workstream F2.

```python
view = sift.as_result(anything_sift_returned_or_fitted)
view.features      # ordered selected names — the ONE canonical accessor (new name, no collision)
view.indices       # positions in the caller's X, or None
view.support_      # boolean mask over input columns
view.encoded_support_  # mask over encoded output columns, or None
view.k
view.table         # alias for raw_table: one row per raw input column
view.encoded_table # one row per encoded output column, or None
view.curve         # k, criterion, criterion_se, selected — same names for every auto-k route
view.metadata      # effective params only; includes schema_version
view.diagnostics
view.proxies(feature, r_min=0.8)
view.plot(ax=None)         # lazy matplotlib
view.to_dict()             # JSON-safe, versioned
view.transform(X)          # column subset; order per output_order (default preserves today's)
view.inverse_transform(X_selected)  # requires retained fitted encoder state
```

- **All existing classes, constructors, defaults, pickle formats, and `isinstance` relations are
  unchanged in 0.9.** `FilterSelectionResult` keeps being returned by `return_result=True`;
  Boruta's `selected_features()` stays a method; `StabilitySelector.selected_features_` stays
  indices for every input type. The view is where unification lives.
- Under the hood, adapters delegate to what each selector already computes; where a value does not
  exist (e.g. Boruta has no per-step path-gain curve even though its stored mean importance maps
  to table `gain`), the column is **absent**, never NaN-padded.

`table` schema: `feature, selected_index, path_rank, selected, relevance, gain,
redundancy_at_selection, reason_dropped` with `reason_dropped ∈ {None, "constant", "top_m",
"corr_prune", "zero_weight_variance", "nonpositive_relevance", "not_reached"}`. This is the
schema for `raw_table`, one row per caller-supplied column. `encoded_table` is separately defined
over encoded output columns and carries `raw_feature`/`block_id` mapping columns; it is not
substituted for `raw_table`. A fitted view may transform raw input through its retained encoder
and inverse-transform selected encoded output. A result-only adapter that lacks fitted encoder
state must set `metadata["transform_available"] = False` and raise a clear `NotImplementedError`
for `transform`/`inverse_transform`; it may still expose names, tables, and metadata. Block
selections additionally expose `block_id` and member columns in `diagnostics`. Per selector,
`gain` is the log-det step gain (CEFS+), JMI increment, score-test gain (binary), `W` (knockoffs),
mean importance (Boruta), or mean |coef| (stability). The legacy CatBoost result does not retain
per-feature score deltas, so its adapter maps the exact stored final-model importance to `gain`
and records `gain_source="final_model_feature_importance"` rather than fabricating a delta.
`features` is the selected raw-feature accessor; encoded names are exposed separately as
`encoded_features` when an encoded representation exists.

**Contract details the view must specify (rev-1 gaps, now normative):**

1. *Duplicate names*: `raw_table` carries `selected_index`; name-keyed accessors raise on ambiguity
   with a message pointing at positional access.
2. *Provenance*: `metadata["input_kind"] ∈ {"dataframe", "positional", "unknown"}` and separate
   `metadata["raw_columns_hash"]`/`metadata["encoded_columns_hash"]`. `"unknown"` is required for a
   legacy result-only adapter that cannot prove whether its source matrix was named or positional;
   `input_features` can establish an ordered identity and hash but must not fabricate historical
   provenance. A view built from a cache records cache provenance (`n_rows_original`,
   `feature_names_are_synthetic`) when the legacy object retained it.
3. *Incomplete rankings*: `metadata["table_complete"] = False` whenever any raw or encoded
   column has no row-level information (e.g. legacy adapters); `plot()`/`proxies()` degrade
   explicitly.
4. *`transform` validation*: same rules as the fitted classes — named inputs validated by name,
   positional by width; positional-fit + DataFrame input raises (mirrors the Stage-0 stability
   fix and the 0.8 cache contract). Encoding-aware transform and inverse-transform additionally
   require the fitted encoder state to have been retained; metadata marks result-only adapters
   without that state as unavailable.
5. *Serialization*: `to_dict()` embeds `schema_version` (starts at `"1"`); consumers must ignore
   unknown keys; DataFrames serialize as `orient="split"`. Ordinary string-key mappings, including
   the payload root and normal metadata, stay plain JSON objects. Only a mapping containing a
   non-string key uses the tagged, ordered
   `{"__sift_mapping__": "typed_key_entries", "entries": [{"key": {"type", "value"}, "value"}]}`
   envelope, so keys such as `1` and `"1"` are never merged; both forms belong to schema `"1"`.
   Unsupported objects raise `TypeError` rather than serializing a `repr()`.
6. *Memory*: `proxies()` works from stored **correlations**, never retained `X`: only an explicit
   `store_proxies=True` opts into storing the selected×candidate float32 block at selection time;
   there is no hidden automatic capture based on block size. When not requested,
   `proxies()` raises with the exact option to pass. The stored block has a documented memory cap
   (default ≤ 64 MiB), and requests exceeding it fail explicitly rather than silently retaining
   `X` or truncating the block.
   The producer coverage is `select_cached`, Gaussian filter routes, and
   opt-in `StabilitySelector(store_proxies=True)`. F2 report methods read the
   same stored block; resample selection indicators used for cluster
   frequencies are separately capped by actual retained bool bytes (default
   ≤ 16 MiB) and omitted from `to_dict()` / JSON.

**Acceptance.** `sift.as_result(x)` works on the output/fitted state of all seven entry-point
families; one "Reading results" doc page runs the same five lines against each; the contract

### E. Categorical story: leakage-safe by construction (M) — **done**

1. **One SIFT engine carries `cat_encoding="target_cv"` for every fold kind.** Rev 1 delegated the
   unweighted, ungrouped case to sklearn's `TargetEncoder` (available since 1.3) and used custom
   splitting only for sample weights, `groups` (GroupKFold folds), and `time` (forward-chained
   folds). Stage 1 replaced that split ownership: sklearn's encoder does not expose the per-fold
   training priors the centering contract in (2) requires, so a two-engine design could not carry
   one guarantee. SIFT's engine now serves all three kinds while preserving the previous fixed-k
   split construction (`KFold`/`StratifiedKFold(shuffle=True, random_state=...)`, same effective
   split count and seed) and reproducing sklearn's `smooth="auto"` empirical-Bayes shrinkage
   exactly, generalized to weighted rows. Semantics are unchanged: internal-CV `fit_transform` for
   selection, target-blind `transform` for inference.

   **Numerics.** Because the emitted quantity is a *difference* from the prior, every moment the
   engine accumulates is taken on `y - prior`, and the within-category sums of squared deviations
   use a two-pass weighted formula rather than `E[y²] - E[y]²`. The raw-moment version lost the
   leading digits of both terms on an offset target: `y + 1e8` moved the emitted effects by up to
   0.185 on the plain path and 0.306 under time-aware folds, and changed which feature `k=1`
   returned on two near-tie designs. The encoding is now invariant to an additive shift of `y`
   (≤5.6e-16 against the shifted target's own quantization) and equivariant under scaling
   (`λ_i` is scale-free, so the effects scale by `s`). Pinned by
   `test_target_cv_auto_smoothing_is_invariant_to_an_additive_target_offset` across the plain,
   weighted, grouped, and time-aware contexts, and at selector level by the two
   `..._selection_is_invariant_to_an_additive_target_offset` tests.
2. **Center every target-derived value on the training prior that produced it.** OOF training
   emits `fold_encoding - fold_training_prior`; inference emits
   `full_fit_encoding - full_training_prior`. Unknown or unseen categories therefore emit a zero
   centered effect (the raw global-mean estimate before centering), and a unique level cannot
   identify its fold through the fold-local prior. The contract applies to the fixed-k,
   weighted, group, and time paths alike, because (1) routes them all through one engine.

   **Scope.** Centering neutralizes *unseen-in-fold* emissions only. It is not a high-cardinality
   defence: a level appearing ≥2 times in a fold's training rows still transmits those sibling
   rows' targets, which is ordinary target-encoding behavior. A near-unique identifier whose rows
   share a latent target therefore remains selectable — measured at `corr(enc, y) ≈ 0.88` on a
   300-ID / 2-rows-each fixture, chosen first by `select_mrmr(k=2)` — and the numerics are
   deliberately unchanged, because that is real cross-row information rather than a fold marker.
   The documented remedies are to drop ID-like columns or to pass `groups=` so an identifier's
   rows share a fold, under which the same column encodes to exactly zero. Pinned by
   `test_near_unique_ids_with_a_shared_target_stay_selectable_by_design`,
   `test_near_unique_ids_without_a_shared_target_are_not_selected`, and
   `test_grouping_an_identifiers_rows_into_one_fold_removes_the_residual`.
3. Normative details rev 1 left open: fold-local m-estimate smoothing
   (`target_cv_smoothing="auto"` reproducing sklearn's empirical-Bayes shrinkage, available on
   every fold kind because the prior generalizes to weighted row mass; an explicit non-negative
   float is equally accepted everywhere); missing values → own category; and a
   stated guarantee: with `groups`/`time`
   provided, no encoded value is computed from its own row's fold, group, or future. Time-aware
   folds are fully specified: rows in the earliest fold have no history and **must not** receive a
   full-data target mean or any other target-derived prior. They receive an explicitly
   user-supplied, target-independent `target_prior` — and, being centered on that prior, emit a
   neutral zero effect — or the caller must select a
   `warmup_policy="exclude"|"zero_weight"` (the latter is the default) that excludes those rows
   from the selection fit. Tied timestamps are never split across a fold boundary and are encoded
   only from strictly earlier times; at inference `transform` applies the encoder fitted on all
   training rows, so unseen or future times are ordinary rows for it. Encoding metadata uses one
   nested schema in every route, with no stray top-level `kind` or `n_splits` keys:
   `encoding_cv.kind ∈ {"fixed_k", "group", "time"}` and `encoding_cv.n_splits` is the effective
   fold count reported by the fitted encoder. Fixed-k selector classes and fixed-k function APIs
   both report `kind="fixed_k"` and continue to reject `groups`/`time` (as in 0.8);
   group/time-aware auto-k selector paths may report `group`/`time` when those metadata inputs are
   accepted. No fixed-k path claims a grouped/time encoding guarantee.
4. Unsupervised fallbacks that never leak: `"ordinal"`, `"frequency"`, `"onehot"`
   (`onehot_max_levels` cap, remainder pooled).
5. **Ordering constraint (accepted from review): minimal block support (F3) lands before one-hot
   encoding ships as a selector option**, so a category enters/leaves as a unit from day one.
6. The `allow_full_data_target_encoding=True` escape hatch and `category_encoders` backends stay
   as the legacy expert path, but the flag is rejected when `cat_encoding="target_cv"` because it
   contradicts the cross-fitted contract. `KnockoffSelector` also rejects `target_cv`: supervised
   target-derived preprocessing invalidates the Model-X exchangeability claim. Legacy supervised
   knockoff encoding remains available only with a warning and explicit metadata that no FDR
   claim applies.

**Acceptance.** `select_mrmr(df_with_strings, y, k=10, task="regression",
cat_encoding="target_cv")` works with no extras installed. For a unique-ID feature, the centered
OOF column has one value, zero variance, and zero relevance, and it cannot outrank a nonconstant
noise feature; exclusion is not required when `k` exhausts every nonconstant candidate. Direct
grouped/time tests prove that mutating held-out-group or future targets does not change the
corresponding encodings. The binary time-route regression fixture with six timestamp blocks and
two zero-weight blocks reports the actual four active folds in both encoder and public-result
metadata, never a reconstructed five.

**Implementation status (E1 + E2 implemented; Stage 1 centering and metadata corrections done).**
Function selectors, the sklearn wrappers, binary CEFS+, and Boruta accept additive
`cat_encoding="target_cv"` without `category_encoders`; weighted, grouped, and temporal routing is
implemented. Training uses OOF transforms and selector inference is target-blind.

**Design decision (Stage 1): all `target_cv` routing goes through SIFT's own engine.** Rev 1 split
the work between sklearn's `TargetEncoder` (unweighted fixed-k) and a SIFT encoder
(weighted/group/time). That split cannot carry the centering contract in (2), because sklearn's
encoder exposes only the final encodings, never the per-fold training priors that centering has to
subtract. Rather than approximate those priors or center only half the surface, one engine now owns
every fold kind. The prior sklearn-path behavior is preserved rather than reimplemented loosely: the
fixed-k folds keep `KFold`/`StratifiedKFold(n_splits, shuffle=True, random_state=...)` with the same
effective split count and seed, and `target_cv_smoothing="auto"` reproduces sklearn's
empirical-Bayes shrinkage `lambda_i = n_i·s²_y / (n_i·s²_y + ssd_i/n_i)` to floating-point equality
on unweighted data (verified at 1.8e-15 max absolute difference against
`TargetEncoder(cv=5, shuffle=True, random_state=0)` once the fold prior is added back), extended to
weighted rows by replacing integer counts with weighted row mass. Smoothing options, group
exclusion, strict-history time folds, tied timestamps, effective weights, the
one-raw-column/one-encoded-column contract, and missing-as-its-own-category are unchanged.
`TargetCVEncoder.fit_mode_` now always reports `"sift"`, and the `encoder_` attribute holding a
fitted sklearn `TargetEncoder` no longer exists.

Emissions are now centered category effects, so the reproduced leak is closed: on the 600-row,
8-seed fixture (unique `id`, 8-level `city` effect, `x1`, `x_noise`, K=5) `select_mrmr(k=3)`
selected `id` in 8/8 seeds with `corr(enc(id), y) ≈ -0.09` before the fix and 0/8 seeds with a
zero-variance constant column after it; group proxies fell from `|corr| 0.38` to 0.00 and timestamp
proxies from 0.97 to 0.00. Metadata is producer-owned throughout: results carry only the nested
`encoding_cv` read from the fitted encoder, the stray top-level `kind`/`n_splits` keys are gone,
`BinaryPathRun` carries the encoder's own metadata so the six-block/two-zero-weight time fixture
reports four active folds rather than a reconstructed five, and a requested-but-absent categorical
column is ignored silently (the established `loo`/`loo_logit` convention) instead of raising
`KeyError: 'encoding_cv'`. `allow_full_data_target_encoding=True` with `target_cv` is rejected at
every entry point, and `KnockoffSelector` rejects `target_cv` outright while downgrading legacy
supervised encodings to `fdr_control="none"` with a warning and a `validity_note`. E is complete and
the acceptance tests above pass in `tests/contracts/test_target_cv_encoding.py` and
`tests/test_release_readiness.py`.

E2 pins four additive options on filter selector functions/classes and Boruta:
`target_cv_n_splits=5`, `target_cv_smoothing="auto"`, `target_prior=None`, and
`warmup_policy="zero_weight"`. Every fold kind accepts `"auto"` or an explicit non-negative float;
weighted/group/time modes use fold-local weighted m-estimates, and `"auto"`'s empirical-Bayes prior
is the unweighted formula with counts replaced by weighted row mass (`prior = Σwy/Σw`,
`s²_y = Σw(y−prior)²/Σw`, `w_i` the category's weighted mass, `ssd_i` its weighted sum of squared
deviations), so weight `m` and `m` duplicated rows encode identically. The adversarial-review round
corrected an earlier gate that rejected `"auto"` on those paths and so made the documented weighted
generalization unreachable; no contextual case was found in which `"auto"` is undefined but an
explicit float is not, and the one genuinely undefined case — a fitting slice with no positive
weight mass — still raises for both.
Integer weights reproduce the corresponding full-fit category maps, zero-weight targets have no
effect, GroupKFold excludes the entire held-out group, and forward time blocks keep tied timestamps
together and use strictly earlier rows. Earliest time rows receive an explicit target-independent
prior — emitting the centered neutral zero effect — or zero effective selection weight

tested count (post-screening; group-level when grouped), not raw `p`. Per-draw counts and
infeasibility are explicit: the scalar `1/min(m)` summarizes the worst-draw count bound, not
aggregate impossibility. `tested_state="not_run"` and separate `n_eligible` distinguish early
returns from completed screening. Counterfactual discoveries count reported features (expanded
group/cluster members), excluding conditioners. Caller-scoped warnings and unchanged selections,
defaults and FDR labels are tested. Clean runtime evidence and final full-suite/CI/merge remain.
(b) **Opt-in**
  `aggregation="evalues"` for `n_draws > 1`, defaults unchanged (Ren & Barber 2022:
  `e_j = m·1{W_j ≥ T_q}/(1 + #{W ≤ −T_q})` per draw). e-BH runs over exactly the common tested
  universe `T`, with `m = |T|`; `m` is not the number of nonzero e-values. A feature screened out
  in draw `d` remains in `T` and contributes `e_j=0` for that draw, rather than being dropped or
  diluting a per-draw denominator. If screening sets vary by draw, `T` is their union and every
  draw uses this same `m`; the sets and zero padding are recorded in metadata. A varying union that
  was not fixed before the knockoff statistics, or a screening rule without the required
  swap-invariance proof, is exploratory and receives no FDR statement. Validated ungrouped mode is
  restricted to shipped statistics whose sign-flip antisymmetry is proved and regression-tested;
  no statistic inherits that status merely by being shipped. Under a validated swap-invariant
  screening rule, **stated precisely**: the FDR guarantee is conditional on Model-X
  exchangeability holding for the plug-in Gaussian-copula knockoff draws — i.e. it inherits the
  library's existing `approximate_plugin` framing, it does not upgrade it; metadata says so.
  Grouped e-value mode is exploratory/no-FDR until a valid group statistic and corresponding proof
  exist. (c) The **statistic bakeoff** the 0.8 docs promised: a committed,
seeded benchmark (independent / AR(1) / block-correlated / dense-weak × {relevance, lsm, ridge,
cefsplus}) with provenance recorded, whose results either justify flipping the default to `ridge`
in 1.0 or keep `relevance` with numbers in the repo. (The review-time measurement — power
0.39 vs 0.90 on AR(1) at equal cost — is currently uncommitted scratch evidence and is treated as
a hypothesis for this benchmark, not as a committed result.)

**F9. `sift.compare` (M) — leakage-safe by design, before manifests.** Rev 1's version (score
precomputed selections by CV on the same data) would leak: a subset selected using all of `y`
must not be evaluated by resampling that same data. Redesign:

```python
sift.compare(
    {"cefs": lambda: CEFSPlusSelector(k="auto"), "fdr": lambda: KnockoffSelector(q=0.1)},
    X, y, estimator=Ridge(), cv=GroupKFold(5), groups=g,
)   # refits SELECTION inside every training fold; scores on the untouched fold
```

Selector *factories*, per-fold selection refit, per-fold downstream fit/score; report score
distribution, mean k, and selection-frequency overlap across folds. A cheap
`mode="in_sample_path"` variant (prefix scoring of a full-data path) exists but is labeled
in-sample in every output. `view.to_dict()`-based **reproducibility manifests** land after this,
reusing its fold bookkeeping. Manifest contents are enumerated now: sift/numpy/pandas/
scikit-learn/scipy/numba versions, BLAS runtimes via `threadpoolctl.threadpool_info()`, git
commit when available, `X` shape + column-name hash (+ opt-in data hash), cache provenance
(`n_rows_original`, synthetic-names flag), the *effective* configuration, seeds, and per-fold
split fingerprints (hashes of index arrays).
