# SIFT 1.0 compatibility proposal

Status: approved for implementation on 2026-09-21, checked against `612368e` /
`0.10.1.dev0`. Approval does not mean these changes have shipped in a release.
Written by Astra after independent Claude Opus xhigh and Grok 4.6 xhigh
proposals and source verification. Both provider runs completed successfully.
This document records the approved policy and implementation boundary.

## Recommendation

Make 1.0 predictable to configure while preserving existing algorithms and
ways of consuming results. Change the three `None` seed defaults, progress,
parallelism and transformer output order. Preserve the existing deterministic
seed-42 defaults. Retain the 66 top-level exports,
legacy result forms and permanent aliases. Keep the scikit-learn 1.3 floor
unless a concrete new feature requires a higher one.

This deliberately narrows the older [1.0 ledger](0.9-product-layer.md#4-deprecation-ledger-everything-that-flips-in-10).
Its planned export removals, tuple deprecation and dependency-floor increase
would add migration costs without being necessary for the default changes.
Accepting this proposal means revising that ledger and any conflicting
runtime announcements together, before 1.0 ships. The existing `None` seed
changes have runtime notices; the other proposed default changes do not.
Recommend an advance 0.10.x release-note/migration announcement for those
changes, with the flips reserved for 1.0 and no new per-call default warnings.
This is an explicit revision of the earlier blanket warning-cycle policy,
not a claim that such a cycle has already happened.

## Defaults to change

| Area and affected APIs | Current behavior | Proposed 1.0 behavior | Compatibility impact |
| --- | --- | --- | --- |
| `StabilitySelector`, `permutation_importance`, `catboost_select` and forwarding convenience functions | `random_state=None` | Default to `0`; preserve explicit `None` where currently supported | Omitted calls use an explicit seed. Stability resamples and importance permutations change; CatBoost currently delegates some seed behavior to its backend. This is not a cross-platform bitwise-reproducibility guarantee. |
| `AutoKConfig`, `evaluate_feature_path`, `SmartSamplerConfig` and their builders | Seed `42` | **Keep `42`** | Already deterministic. Changing it would alter folds, samples and potentially selected features solely to standardize a number. This reverses the ledger's “0 everywhere” recommendation. |
| Filter functions and wrappers | Function omission sentinel or wrapper `random_state="auto"`, resolving to `0` without a cache | Keep those signatures and the effective seed `0` | The omission marker distinguishes an unused seed from an explicitly supplied seed beside a prebuilt cache. Replacing it with literal `0` would damage that contract. |
| APIs with `verbose=True`: filters, Boruta, stability, CatBoost, `Stabilized`, sampling config and forwarding functions | Progress enabled | `verbose=False` | Less progress output. Explicit `True`, callbacks and correctness warnings retain their meaning. `ModelSelector` already defaults to `False`. |
| `StabilitySelector`, `permutation_importance`, `catboost_select` and forwarding functions | `n_jobs=-1` | `n_jobs=1` | Lower default resource use, potentially longer runtime. Explicit parallel settings remain available where supported. |
| Ten selector transformers exposing `output_order` | `"legacy"` | `"original"` | Selected transformed columns follow fitted input order. Selection membership and discovery/ranking order are unchanged. |

The transformer set is `MRMRSelector`, `JMISelector`, `JMIMSelector`,
`CEFSPlusSelector`, `CEFSPlusBinarySelector`, `KnockoffSelector`,
`BorutaSelector`, `StabilitySelector`, `ModelSelector`, and `Stabilized`
(**ten** classes). Boruta's current legacy order is already original order.
For one-hot transforms, order selected raw parents by fitted position while
preserving the established dummy order within each parent. Keep
`get_support(indices=True)` and `get_feature_names_out()` aligned with
transformed columns. `selected_features_`, result tables and function-returned
selection paths keep their existing ranking/selection conventions. Preserve
the nested auto-k clone's explicit `output_order="legacy"`: prefix evaluation
must use the learned path, even when the final transformer uses input order.
That override already exists in `_clone_for_nested_path`.

The parallelism proposal applies to SIFT's existing public worker-count
parameters, not every thread in the process. It does not override supplied
estimators, BLAS settings or GPU behavior. Boruta has no public `n_jobs`
parameter and builds parallel forests internally; leave that separate policy
unchanged in this scope. `Stabilized` already accepts only `1` or `None`, both
serial; it must not gain an unsupported `-1` setting for uniformity.

## Interfaces to retain

- **All 66 current top-level exports**, including `CompareResult`,
  `ClassicFeatureCache`, `build_classic_cache` and the research helpers.
  Keep `sift.experimental` available. Revise its announcement about the
  pre-1.0 transition to match the approved import policy; do not create a
  forwarding layer for imports that can simply remain in place.
- **Existing list, tuple and result-object returns.** `select_cached` returns
  a list by default; tuples arise only from its objective/index flags. Keep
  all those forms, with `return_result=True` / `as_result` as the recommended
  opt-in interface. Do not change every function to return a new shared class.
- **Selector mathematics and count defaults**, including
  `select_fdr(statistic="relevance")` and `select_cefsplus(k=75)`. Consistent
  configuration is not evidence for a different feature-selection policy.
- **Permanent aliases**: CatBoost `group_col` / `sample_weight_col` and
  stability `alpha` / `penalty`. Also retain the flat `AutoKConfig` storage
  contract, its group builders, and the documented
  `StabilitySelector.selected_features_` convention.
- **scikit-learn >=1.3.** The 1.4 floor would let all supported installations
  use newer metadata-routing APIs, but no proposed default change needs it.
  Existing tests already gate those APIs by version. Raise the floor only
  with an approved feature or demonstrated maintenance burden that needs it.

One related choice must be explicit: `catboost_params` currently overrides
translated SIFT options, and a runtime warning promises conflicting values
will be rejected in 1.0. Introducing default seed `0` and worker count `1`
would create collisions for callers who already set `random_seed` or
`thread_count` there. **Recommend retaining the override precedence**, with
accurate conflict guidance, and withdrawing the promised blanket rejection.
The existing backend already implements that precedence; keep its override
warning with corrected wording. New translated defaults can introduce an
override warning for an existing `catboost_params` setting; callers treating
warnings as errors need that called out in the migration note. Do not add a
new parameter-resolution system or claim that warnings remain identical.

## How the three proposals were reconciled

| Choice | Independent input | Combined decision |
| --- | --- | --- |
| Existing seed `42` | Both Opus and Grok recommended retaining it; Astra initially proposed `0`. | Adopt their narrower change: deterministic results should not change for numerical uniformity. |
| Public exports | Opus proposed 50, Grok 51; Grok correctly retained `FeaturePathEvaluationResult` beside its public producer. | Keep all 66. Neither proposal established a consumer or maintenance need for breaking imports. Experimental placement can guide discovery without deleting working imports. |
| sklearn floor | Both proposed 1.4 to remove metadata-routing gates. | Keep 1.3. Newer routing already runs on newer supported versions; removing gates is insufficient reason to drop a passing supported environment. Revisit for a concrete feature need. |
| CatBoost conflicts | Grok proposed honoring the announced 1.0 rejection. | Retain explicit dictionary overrides: new implicit seed/thread defaults otherwise make previously valid backend configuration conflict. Correct the prior announcement openly. |

All three views retain tuple returns. This proposal also keeps permanent
aliases, `k=75`, the default knockoff statistic, distinct `AutoKConfig` fields,
and the current `StabilitySelector` implementation. Becoming a `Stabilized`
preset is a separate algorithm/architecture proposal. The nested-path ordering exception and
explicit `output_order="legacy"` option are retained from the source-checked
review. This synthesis prioritizes a demonstrated user benefit over the
number of reviewers favoring a change.

## Migration examples

These examples use interfaces available today. Explicit settings let callers
choose behavior before the version changes.

Adopt the proposed defaults now for a stability transformer:

```python
from sift import StabilitySelector

selector = StabilitySelector(
    random_state=0, verbose=False, n_jobs=1, output_order="original"
)
```

Preserve the current default choices across the transition:

```python
from sift import AutoKConfig, SmartSamplerConfig, StabilitySelector

selector = StabilitySelector(
    random_state=None, verbose=True, n_jobs=-1, output_order="legacy"
)
auto_k = AutoKConfig(random_state=42)
sampler = SmartSamplerConfig(random_state=42, verbose=True)
```

Explicit `None` preserves the request for entropy, not a previous random
realization. For replay, supply the recorded realized seed where available.
The two explicit `42` settings above, and
`evaluate_feature_path(..., random_state=42)`, are optional under this
proposal because those defaults remain unchanged. Configuring the selector
seed alone does not configure an
explicitly supplied `AutoKConfig` or downstream estimator.

Choose output order independently of the discovered feature ranking:

```python
from sift import CEFSPlusSelector

selector = CEFSPlusSelector(k=2, verbose=False, output_order="original")
selector.fit(X, y)
X_selected = selector.transform(X)
column_names = selector.get_feature_names_out()
```

Here `X` and `y` are the caller's training data. Use `output_order="legacy"`
to preserve current transform order. Refit a downstream model when changing
the transformed column order; do not feed reordered arrays into an already
fitted model. No tuple-return migration is required under this proposal.

## Implementation after approval

1. Update the 1.0 ledger and migration text to record the accepted decisions,
   including retained seed-42 defaults, export and CatBoost announcements,
   and the revised notice policy. Keep the duplicated ledger tables
   consistent. Announce the changes before releasing 1.0.
2. Change the existing defaults and the wrapper/builder forwarding sites
   together. Preserve omission markers, explicit seeds, cache rules,
   configuration values and estimator-specific options.
3. Extend existing signature/default and transformer contracts. Prove new
   omitted calls equal their explicit new settings, explicit legacy settings
   retain behavior, and original-order output preserves feature membership,
   names and one-hot grouping. Cover the existing nested path-order override
   and use existing fixed-seed parallelism comparisons where available;
   add only missing checks needed for the changed defaults. Reuse the
   cached-return, clone, routing and public-export contracts. Avoid a new
   validation framework or a separate PR per trivial default assignment.
4. Run the affected tests, generated docs and existing Python 3.11–3.13,
   minimum-pins and optional-dependency CI jobs on the implementation PR.
   Refresh source-bound runtime evidence only as required by actual source
   changes; keep frozen quality evidence intact. Version/tag/release work
   follows a separate release decision.

## Approved decisions

The owner approved the four default changes with the cache and parallelism exceptions;
keep existing seed-42 defaults, exports, returns and the sklearn 1.3 floor;
retain CatBoost parameter override precedence; and approve the advance
release-note/migration notice policy. Version bumps, tagging and publication
remain separate release actions.
