## Stage 1 — correctness and contract repair

No new capability work starts until this stage is complete.

### 1.1 Center target encodings on fold-local priors — **done**

Emit centered category effects rather than raw fold target means:

- OOF training: `encoded_effect = fold_encoding - fold_training_prior`.
- Inference: `encoded_effect = full_fit_encoding - full_training_prior`.
- An unseen or unique category therefore emits zero, the centered equivalent of the raw global
  prior, rather than a value identifying its fold.
- Apply the rule to fixed-fold encoding and SIFT's weighted, group, and time encoders.
- Keep smoothing, group exclusion, strict-history time folds, tied timestamps, effective weights,
  and the one-raw-column/one-encoded-column contract unchanged.
- Earliest temporal rows with an explicit target-independent prior emit a centered neutral effect;
  without one they retain zero effective selection weight.
- Update user-facing wording from “unknown maps to the global mean” to “unknown maps to zero
  centered effect (the raw global-mean estimate before centering).”

**Design decision taken during implementation:** all `target_cv` routing moves to SIFT's own
engine. sklearn's `TargetEncoder` never exposes the per-fold training priors centering must
subtract, so a two-engine design could not carry one guarantee. Fixed-k split construction
(`KFold`/`StratifiedKFold(n_splits, shuffle=True, random_state=...)`), the effective split count,
the seed, and `smooth="auto"` empirical-Bayes shrinkage are all preserved — the reimplemented
`"auto"` matches sklearn to 1.8e-15 on unweighted data and generalizes to weighted rows by
replacing integer counts with weighted row mass. Recorded in
[the campaign spec](0.9-product-layer.md) §E implementation status.

Acceptance (all covered by `tests/contracts/test_target_cv_encoding.py`, plus release-gate
coverage in `tests/test_release_readiness.py`):

1. A unique-ID column has one constant OOF value and zero variance.
   `test_unique_id_column_has_one_constant_oof_value_and_zero_variance`.
2. The ID has zero relevance and never outranks a nonconstant noise feature. Do not require its
   exclusion when `k` exhausts all nonconstant candidates.
   `test_unique_id_never_outranks_a_nonconstant_noise_feature_in_mrmr` (k ∈ {2, 3} × 8 seeds),
   `test_unique_id_carries_zero_relevance_in_the_reported_ranking`,
   `test_unique_id_never_outranks_noise_on_cefsplus_routes`
   (`penalized_objective`, `gaussian_cv`, and the no-config router), and the explicit carve-out
   `test_requesting_every_column_still_succeeds_without_requiring_exclusion`.
3. Grouped and temporal proxies do not gain relevance from complement-fold priors.
   `test_group_proxy_gains_no_relevance_from_complement_fold_priors` and
   `test_timestamp_proxy_gains_no_relevance_from_complement_fold_priors`.
4. Mutating held-out group/future targets leaves the corresponding centered effects unchanged.
   `test_mutating_held_out_group_targets_leaves_centered_effects_unchanged` and
   `test_mutating_future_targets_leaves_earlier_centered_effects_unchanged`.
5. Known, missing, and unseen inference categories remain deterministic after pickle round-trip.
   `test_inference_categories_are_deterministic_after_pickle_round_trip`.

**Evidence.** On the reproduced 600-row, 8-seed fixture (unique `id`, 8-level `city` effect, `x1`,
`x_noise`, K=5), `select_mrmr(k=3, cat_encoding="target_cv")` selected `id` in 8/8 seeds with
`corr(enc(id), y)` between −0.061 and −0.133 before the fix; after centering the column is a
zero-variance constant, `corr` is exactly 0, and `id` is selected in 0/8 seeds. Group proxies fell
from `|corr|` 0.383 to 0.000 and timestamp proxies from 0.966 to 0.000. Four existing tests whose
pinned values assumed raw-prior emissions were updated: the two time-fold fixtures now carry two
categories so centering leaves a real contrast (a single-category column correctly collapses to
zero, pinned separately), the unknown/missing inference test pins the zero centered effect instead
of `encoder_.target_mean_`, and the OOF-vs-inference selector test uses a low-cardinality column
because a unique-ID column is now constant and therefore not a selectable candidate.

### 1.2 Repair target-encoding routing and metadata — **done**

- Preserve only the nested metadata shape
  `encoding_cv={"kind": ..., "n_splits": ...}`; remove stray top-level `kind` and `n_splits`
  currently emitted by classic and Gaussian function results.
- Carry the encoder's actual binary metadata through `BinaryPathRun`; do not recompute split counts
  from all rows when zero-weight rows were inactive.
- Pin the reproduced binary time-fold fixture: with six timestamp blocks and two zero-weight
  blocks, both the fitted encoder and the public rich result report
  `encoding_cv={"kind": "time", "n_splits": 4}`. The current reconstructed value of five is a
  regression.
- Attach encoding metadata only when categorical encoding was actually applied. A requested but
  absent categorical column must not cause `return_result=True` to fail.
- Reject `target_cv` together with `allow_full_data_target_encoding=True` across function,
  selector, binary, and Boruta entry points.
- Reject `target_cv` in `KnockoffSelector`. Retain 0.8 supervised-encoding compatibility only with
  an explicit warning and `fdr_control="none"` metadata, because target-derived preprocessing does
  not retain the Model-X claim.
- Keep fixed-k `groups`/`time` rejection, multiclass rejection, and the default
  `cat_encoding="none"` unchanged.

**Evidence.** `_target_cv_metadata`'s request-side reconstruction is deleted; the only producer of
encoding metadata is `target_cv_metadata_from_encoder`, fed by the fitted encoder's `encoding_cv_`
through `ClassicPrepared.target_cv_metadata`, the Gaussian cache builder, and the new
`BinaryPathRun.encoding_cv` field. Covered by
`test_target_cv_metadata_emits_no_stray_top_level_fold_keys` (all four function routes),
`test_binary_time_route_reports_the_encoders_active_fold_count` (encoder and public rich result
both `{"kind": "time", "n_splits": 4}` on the six-block/two-zero-weight fixture; the reconstructed
value was five), and `test_requested_but_absent_categorical_column_does_not_break_rich_results`
(previously `KeyError: 'encoding_cv'` on the binary route). The requested-but-absent convention was
determined by reproduction: `loo`/`loo_logit` ignore an absent `cat_features` column silently on
both the binary and filter routes, so `target_cv` now does the same rather than raising. C3 is
covered by `test_function_routes_reject_target_cv_with_full_data_escape_hatch` and
`test_selector_classes_and_boruta_reject_the_full_data_escape_hatch`; C4 by
`test_knockoff_selector_rejects_target_cv`,
`test_knockoff_legacy_supervised_encoding_warns_and_drops_the_fdr_claim`, and the scoping guard
`test_knockoff_without_supervised_encoding_keeps_its_fdr_claim`.

### 1.3 Close the sklearn regressions — **done**

- Make dense validation safe for array-like/duck-typed input without invoking an unsupported
  `__array_function__`; detect complex dtype after safe materialization.
- Use sklearn-compatible wording: `Complex data not supported ...`.
- Store `feature_names_in_` as sklearn's required one-dimensional NumPy object array for both
  named and positional fits. Preserve generated `x0...` names in that public attribute for
  positional fits because this is existing 0.8 behavior; use a separate provenance marker where
  code must distinguish named from positional input. Apply the shared convention to filter
  selectors, Knockoff, Boruta, and Stability.
- Set the legacy `binary_only=True` tag for `CEFSPlusBinarySelector`. On sklearn's object-tag API,
  document and test the nearest valid representation rather than turning the transformer into a
  classifier merely to obtain a tag.
- Pin `check_sample_weights_not_an_array`, `check_transformer_data_not_an_array`,
  `check_complex_data`, and `check_dataframe_column_names_consistency` where applicable.

## Stage 3 — documentation and release readiness

### 3.1 Resolve the deprecation-policy contradiction

The campaign cannot promise a 1.0 warning cycle while leaving slated aliases silent. This is a
release gate, but it does not block the first CI-backed integration of the correctness repairs.

- Wire caller-facing `FutureWarning`s for removals that can be distinguished without changing
  defaults or object identity.
- If a planned removal cannot receive a real 0.9 warning path while preserving the compatibility
  matrix, defer or remove that flip from the 1.0 ledger instead of claiming it is deprecated.
- Add production warn-and-forward tests; helper-only tests are insufficient.
- Reproduce the final, internally consistent ledger verbatim in the release notes.

### 3.2 Complete documentation and release preparation

- Refresh README with `SelectionView`/`as_result`, `target_cv`, `output_order`, metadata routing,
  Auto-K presets/option groups, and `sift.experimental`.
- Replace stale `TODO.MD` version, test-count, target-encoding, and release text.
- Consolidate the release notes into one truthful `0.9.0` section, reproduce the deprecation
  ledger, and state that 0.9.0 supersedes the never-released 0.8.0 work.
- Complete the documented G-docs gate: substantive numpydoc docstrings for every public export, a
  generated reference, and execution of every manual code block in CI. If any item is deliberately
  moved to 0.9.1, amend the campaign Definition of Done before calling 0.9.0 ready.
- Keep `__version__="0.9.0a1"` through integration. Change it to `0.9.0` only in a small release
  PR after Stage 2 is green.
- No PyPI publication. A `v0.9.0` tag/GitHub Release is an explicit owner action after the release
  PR and asset-only workflow are merged; it is not part of routine implementation.
- After any requested release, bump the development version to `0.9.1.dev0` in a separate commit.

## Stage 4 — resume the 0.9.x capability campaign

After the release gate, reduce collision risk before adding more large features:

1. Split `selection/view.py`, `selection/filter_auto_k.py`, and `selection/auto_k.py` along their
   existing adapter/router boundaries without changing behavior.
2. Add leakage-free unsupervised `ordinal` and `frequency` categorical fallbacks.
3. Continue the accepted capability order:
   - F1 conditioning sets;
   - F2 proxy/cluster reports;
   - F7 panel within/between transforms;
   - F8a knockoff feasibility/UX;
   - F8b/F8c validated aggregation and statistic bakeoff;
   - F3 block-aware selection;
   - E4 one-hot encoding, only after F3 makes a block the selection unit;
   - F9 leakage-safe `sift.compare`, with selector fitting inside every fold;
   - reproducibility manifests;
   - F4 generic `Stabilized`;
   - F5 multi-target selection;
   - F6 generic `ModelSelector`.

Each capability remains independently gated by its API contract, quality evidence, documentation,
and focused tests. A clean release gate does not authorize changing the documented `select_fdr`
statistic or `k=75` defaults; those remain evidence-backed owner decisions.
